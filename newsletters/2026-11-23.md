## In Depth

### Claude Code Adds Experimental Code Mode to Orchestrate Tool Calls with JavaScript

Anthropic just shipped Code Mode for Claude Code, an experimental feature that changes how the model interacts with tools. Instead of requesting individual Bash, Read, or Edit operations one at a time, the model now writes JavaScript to orchestrate them all in one script.

Code Mode is opt-in—off by default—and requires Claude Code v2.1.323 or later plus the CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 environment variable. Anthropic warns it may change or disappear in any release. The idea: one script can run commands in parallel, pipe results between calls, and return only the output the model needs. The documentation example finds a file with ripgrep, raises a retry limit, runs tests, and returns just the path and test output. Each tool call and diff still appears in the conversation UI, with the generated code visible in the transcript viewer.

Anthropic recommends it for edits repeated across many files, searches that need filtering, and independent commands. Code that Claude waits on stops after ten minutes; sessions in auto or bypassPermissions mode can push it to the background for up to two hours while the conversation continues. The permission model is crucial: each call inside the script still goes through deny and ask rules and PreToolUse hooks, but in auto mode the classifier reviews the entire script before it runs—not each call individually—and can't see values computed at runtime. Hooks must check every part of a command because git push might reach a hook as cd 'app' && git push.

Code Mode only runs in interactive terminal sessions of the native build, on Opus 5.5, Sonnet 5.5, Haiku 5.5, or Fable 5.2, through a Claude subscription or Console account. It doesn't work with the -p flag, the Agent SDK, VS Code panel, Desktop app, Amazon Bedrock, gateways, or zero-data-retention organizations. Anthropic hasn't published token or latency figures. Early testing by George (@bolyki) showed identical results, 20–25% smaller context, 37% fewer tokens, and 19% lower cost on a bigger task—but no speed improvement, and higher cost on tiny tasks. Ravi Madabhushi, who builds agent auth infrastructure, clarified it doesn't materially change authentication, authorization, or audit policy layers—the same MCP calls happen with the same tokens; what changes is how much context fits in the model window.

### Claude Code Has Been Leaking Secrets through its "Don't Ask Again" Feature

Security firm Apiiro discovered that Claude Code has been exposing secrets in public repositories due to how it stores command approvals on developers' machines. When you reply "Yes, and don't ask again" to approve a shell command, Claude Code saves it as a permanent permission rule in .claude/settings.local.json—which may inadvertently contain embedded credentials, passwords, and API tokens.

The problem: when Claude Code creates this file inside a git repo, it adds it to your global gitignore list. That covers the common case. It doesn't cover a folder that becomes a repo later, a clone on another machine, or a file someone already committed. The rule never goes into the repo's own .gitignore, so nothing travels with the project to protect it. On some occasions, Claude Code itself committed the file. Apiiro identified 1,122 secrets in settings.local.json files and another 1,160 in git history, shared settings.json files intentionally committed, and agent chat transcripts stored in repos. Sixty-three organizations were affected, with exposed secrets including cloud API keys, production passwords, access tokens, and npm tokens.

Generic secret scanners like gitleaks and TruffleHog failed to flag many exposed secrets because they were embedded inside shell commands rather than stored in key-value format. The same password-in-a-command pattern appears wherever an agent records what it ran: transcripts, memory files, handoff notes. Apiiro also notes the way Claude Code manages secrets is itself a security gap—to any malware, "it's a list of the systems the developer can reach and the passwords that open them, one file search away," available at the same path in every project. GitGuardian later found 31,088 secrets in .claude/settings.local.json on public GitHub, 5,343 of which were still valid at detection, plus another 613 in Docker Hub images.

At minimum, Apiiro recommends untracking the JSON file with git rm --cached .claude/settings.local.json, adding it to the repo's .gitignore, and rotating every credential the file has ever contained. For a sounder approach, inspect the file and delete any rule containing a secret, and avoid typing secrets directly into commands—reference them through environment variables instead. One Reddit user suggested stopping the practice of adding AI files into projects entirely, moving to a memory/task/docs server through MCP instead.

### What is an embedding, really? Building an AI agent from scratch in Java, part 2

This is the second part of a series where the author builds an AI agent entirely by hand in Java—no frameworks, just plain code—to understand how AI engineering really works. In part one, they built an MCP server, MCP client, and agent loop so a local Qwen model running in Ollama could read and write a notes file. But that agent had a catch: it handed the model the entire notes file pasted into the prompt. Fine for a short to-do list, disastrous for a wiki with hundreds of pages.

What the agent really needs is to pull in only the few paragraphs that matter for the question. To find those, it has to search by meaning—not just exact word matches. That's where embeddings come in. An embedding is a list of numbers that represents the meaning of a piece of text. You get one by sending text to an embedding model. The author runs theirs locally with Ollama using nomic-embed-text. Send it "things to buy" and you get back 768 numbers. Every piece of text—three words or three paragraphs—comes back as exactly 768 numbers. That fixed length is what makes texts comparable.

An embedding model isn't a chat model. It's a neural network, but a small one (nomic-embed-text is about 270 MB versus 4.7 GB for Qwen). Text goes in, numbers come out. Nobody chose what the numbers mean—there's no "number 42 = food." The model invented its own 768 features during training. You can't read them, but you can compare them. The tutorial walks through storing embeddings in Postgres, then searching them by meaning instead of exact words using cosine similarity. Classic keyword search (SQL LIKE, full-text search, even Elasticsearch out of the box) works on words—great when you know the exact word, useless when you don't. With embeddings, searching "things to buy" finds "Grocery list" even though they share no words in common.

The post is remarkably clear and hands-on, building everything from scratch so you understand what's happening under the hood. By the end, you've got semantic search working on your own machine with nothing but Java, Postgres, and an embedding model.

### Spring AI's Model Layer: One API, Any Provider, Zero Rewrites

Spring AI tackles a persistent pain point in AI integration: provider lock-in. When you build against one provider's SDK and later need to switch—due to business decisions, pricing changes, or compliance—your code is full of provider-specific request objects, response parsers, and retry rules. Spring AI's model layer provides a unified API that abstracts away provider differences, so you can swap OpenAI for Anthropic or Gemini without rewriting integration code. The post walks through how this abstraction works in practice and why it matters for production AI features.

### CVE-2026-114938 Java4Shell: Pre-Auth RCE in OpenJDK Base64 Decoder — Analysis & Mitigation

Security firm Calif disclosed a critical vulnerability in OpenJDK dubbed Java4Shell (CVE-2026-114938)—a heap out-of-bounds write in the hardware-accelerated Base64 decoder that HotSpot uses to speed up java.util.Base64. A single malformed Base64 string, supplied before any login, can corrupt the Java heap. Calif demonstrated that this can lead to pre-authentication remote code execution. The post provides technical analysis of the flaw and covers mitigation strategies for affected Java applications. This is a serious vulnerability that Java developers need to understand and patch immediately.

*[Dev.to Java](https://dev.to/iamfaizanakhtar/cve-2026-114938-java4shell-pre-auth-rce-in-openjdk-base64-decoder-analysis-mitigation-38ho)*
