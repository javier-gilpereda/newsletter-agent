### ArchUnit as a Guardrail for AI-Generated Code

AI agents can churn out code at remarkable speed—new endpoints, services, repositories—but they don't always respect your project's architecture. They optimize locally, invent arbitrary abstractions, and sometimes reinvent the wheel instead of importing existing solutions. The result? Architectural drift that can quietly undermine your codebase.

Enter ArchUnit, a library that tests Java architecture by analyzing bytecode. It lets you define rules as ordinary automated tests: controllers can't access repositories directly, services can't depend on controllers, repositories must follow naming conventions, and so on. If a rule is violated, the build fails. Simple, effective, and automated.

What makes this especially clever for AI-generated code is the concept of hidden test suites. Some architectural rules shouldn't be exposed to the AI agent or included in its context. These hidden checks verify that changes genuinely follow your principles rather than just gaming the rules the agent already knows about. They complement the explicit rules that describe your expected structure.

ArchUnit can enforce layering, naming conventions, annotation usage, cyclic dependency prevention, and even custom conditions—like ensuring all implementations of a specific interface inherit from a required base class. The article shows a practical example: a Spring Boot project where controllers, services, and repositories live in separate packages, and ArchUnit ensures they stay in their lanes.

This approach doesn't eliminate the need for code review, but it catches architectural violations early and consistently. As AI agents become more capable, the tooling around them needs to mature too. ArchUnit offers a pragmatic way to keep generated code aligned with the architecture you actually want—not just the code that compiles.

### HTTP/3 Support in HTTP Client API in Java 26

Java 26 brings HTTP/3 support to the HttpClient API, marking a significant step forward for modern Java networking. HTTP/3, built on the QUIC protocol, offers faster connection establishment, improved performance over unreliable networks, and better handling of packet loss compared to HTTP/2. For applications making frequent API calls or serving users on mobile networks, this matters.

The implementation in Java's HttpClient is designed to be straightforward. Developers can configure their clients to prefer HTTP/3 while maintaining backward compatibility with HTTP/2 and HTTP/1.1. The API handles protocol negotiation automatically, falling back gracefully when HTTP/3 isn't supported by the server or network infrastructure.

What's particularly useful is that existing HttpClient code requires minimal changes to take advantage of HTTP/3. You're mostly adding a version preference configuration. The underlying QUIC transport handles connection multiplexing, reduces head-of-line blocking, and improves resilience when switching between networks—think mobile users moving from Wi-Fi to cellular.

There are practical considerations, of course. HTTP/3 requires UDP support, which some corporate firewalls still block. Not all servers support it yet, though adoption is growing rapidly among major CDNs and cloud providers. And while performance improvements are real, they're most noticeable in high-latency or lossy network conditions rather than fast, stable connections.

For Java developers building modern applications—especially microservices, mobile backends, or anything dealing with external APIs—HTTP/3 support in the standard library is a welcome addition. It's not a revolutionary change, but it's a solid, forward-looking enhancement that brings Java's networking stack in line with current web standards.

### Spring Tools 5.4.0 Released with Claude Code Integration

Spring Tools 5.4.0 just landed, and it brings official support for Claude Code alongside the usual suspects: VS Code, Cursor, Eclipse, and Theia. This marks a notable moment in the convergence of traditional IDE tooling and AI-powered development environments.

The standout feature for Claude Code users is the ability to render a project's logical structure through the Model Context Protocol (MCP). This means Claude can understand your Spring application's organization—beans, components, module boundaries—not just as a pile of files but as architectural concepts. That's a meaningful step beyond basic code completion.

Beyond the AI integration, this release includes practical developer quality-of-life improvements. There are new validations and quick fixes for converting to modern Spring annotations: @ApplicationModuleListener for event handling, @SpringJUnitConfig for test setup, @RestController for REST endpoints, and specific @Scope annotations. These aren't flashy, but they save time and reduce boilerplate.

Performance improvements focus on the everyday stuff that adds up: faster quick fixes, more efficient validation of repository-based dependency versions, and more reliable indexing of source code. Stability matters when you're context-switching between code, tests, and configuration all day.

The Claude Code integration is particularly interesting given the broader conversation about AI coding assistants. While tools like GitHub Copilot focus heavily on code generation, this integration emphasizes structural understanding. It's less about "write this for me" and more about "help me navigate and refactor this existing system."

For teams already in the Spring ecosystem, the update is worth grabbing. The next release (5.5.0) is scheduled for mid-December, suggesting a steady cadence of improvements as the tooling adapts to the AI-augmented development workflow.

*Source: [Spring Blog](https://spring.io/blog/2026/09/09/spring-tools-5-4-0-released)*

### Dynamic Arrays, Spill, and LET: What Changed in Excel and Why It Matters for Java Applications

Modern Excel has evolved significantly with dynamic arrays, spill ranges, and the LET function, and these changes matter if your Java application processes spreadsheets. Dynamic arrays automatically expand results across multiple cells, fundamentally changing how formulas work. The LET function enables named variables within formulas, making them more readable and efficient. For Java applications that read, write, or calculate with Excel files, understanding these features is crucial—especially when users upload files with modern formulas that older libraries can't handle. This article walks through what changed in Excel's formula engine and how Java tools are adapting to support these capabilities without breaking existing workflows.

### How Will We Train Developers If AI Does the Routine Work?

In this podcast conversation, Scott Hanselman tackles a crucial question: if AI agents handle most routine coding tasks, how do we train the next generation of developers? Traditionally, junior developers learned by doing repetitive work—writing CRUD endpoints, fixing bugs, implementing features. If that work disappears, the learning path breaks down. Hanselman suggests the software industry should adopt a preceptorship model similar to nursing, where experienced practitioners directly mentor newcomers through supervised practice. It's a thought-provoking discussion that goes beyond the usual AI hype to address a real structural challenge facing the industry as automation reshapes how software gets built.

### Shopify Returns to Native Mobile Development

Shopify is moving away from React Native back to separate Swift and Kotlin codebases for their mobile apps. The reason is straightforward: the original goals (avoid building features twice, enable cross-stack development, reduce feature parity work) didn't materialize as hoped. Native development still means maintaining two platforms, but the performance, tooling maturity, and platform integration benefits apparently outweigh the code-sharing advantages. It's a notable reversal from a major tech company and a reminder that architectural decisions need continuous reevaluation based on actual team experience, not just theoretical benefits. For teams considering cross-platform frameworks, it's a useful data point about the real tradeoffs involved.

*[Simon Willison](https://simonwillison.net/2026/Sep/10/shopify-react-native/)*
