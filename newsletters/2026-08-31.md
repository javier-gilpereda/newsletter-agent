## In Depth

### Breaking Claude Code Opus 5 Auto Mode

Security researcher Johann Rehberger has exposed a critical vulnerability in Claude Code Opus 5's Auto Mode that achieves code execution with a 60-80% success rate—despite Anthropic-commissioned testing showing 0.00% prompt injection vulnerability. The attack is deceptively simple: ask Claude to summarize a malicious website, and through a clever chain of individually benign-looking steps, gain full code execution.

Here's how it works: The attacker's website returns a 415 error to Claude's WebFetch tool, nudging it toward using curl instead. A redirect leads to a ZIP archive containing seemingly legitimate catalog files plus a poisoned struct.py. Claude's safety guardrails refuse to run a suspicious binary decoder—but ironically, this triggers the exploit. Claude writes its own Python decoder, which imports base64, which in turn imports struct. Python's module shadowing causes the malicious local struct.py to load instead of the standard library version, executing attacker-controlled code.

The implications are serious. Auto Mode became the default in mid-August, and while Anthropic maintains the behavior is "working as designed," calling it a "best-effort classifier, not a security guarantee," the research highlights a fundamental tension in AI agents: convenience versus security. The attack can even spawn a nested Claude instance with full tool access. Rehberger's key takeaway: run coding agents in proper sandboxes with OS isolation and network egress controls. Trust the environment, not the model output. This serves as a stark reminder that AI safety layers—model training, input probes, intent classifiers—can still be defeated by determined, targeted attack chains that exploit the model's own problem-solving instincts.

### Researcher shows how Claude Code can be tricked simply by asking it to summarize a website

The Register's coverage of Johann Rehberger's Claude Code vulnerability adds crucial context to the security implications. The attack starts innocuously—just asking Claude to summarize a website—but exploits a sophisticated understanding of both AI behavior and Python's module system. The 80% success rate across small sample testing suggests this isn't a fluke but a reproducible attack vector.

What makes this particularly concerning is the obfuscation layer: Rehberger used ChatGPT to obscure the malicious struct.py code enough to bypass Claude's safety controls. The poisoned file launches a separate Python process that downloads and executes remote payloads—in the demo, a command-and-control callback opening Calculator, but real attackers would obviously do worse. More alarmingly, the attack can spawn a headless nested Claude instance via "claude -p", creating an entirely new agent with its own tool access and context that can perform reconnaissance and write to local files.

Anthropic's response is telling: they told Rehberger the behavior is "working as designed" and that Auto Mode is a "convenience feature backed by a best-effort classifier, not a security guarantee." The classifier isn't built to stop determined prompt-injection chains composed of individually innocent-looking steps. The real security boundary, according to Anthropic, is OS isolation and network egress control.

This echoes a pattern we've seen before with AI security: vendors emphasizing that their products need external guardrails rather than being inherently secure. For developers using Claude Code or similar agents, the message is clear: sandbox everything, monitor network activity, and don't trust model output as a security boundary. The convenience of Auto Mode comes with real risks that proper infrastructure must mitigate.

*Source: [The Register](https://www.theregister.com/research/2026/08/28/researcher-shows-how-claude-code-can-be-tricked-simply-by-asking-it-to-summarize-a-website/5293372)*

### OpenAI Is Developing a 'Persistent' AI Agent

OpenAI is quietly testing a game-changing feature for its Codex AI agent: Persistent mode. According to code changes spotted in Codex's command line tool, this new mode would allow agents to "continue working until put to sleep"—a stark departure from current behavior where agents stop after minutes or hours, even with unfinished work.

The feature appears in Codex's "reasoning effort" menu alongside other computational intensity settings. What makes it particularly interesting is the "proactivity" component: agents in Persistent mode are instructed to create follow-up tasks for themselves after completing user requests. They can work across sessions, draw on past interactions and user knowledge, and even message users proactively—though they're told to do so sparingly. The system prompt sets limits too: persistent mode doesn't expand what agents can do, and altering anything outside the user's system requires approval.

The code sits in Codex's shared core rather than terminal-specific sections, suggesting this functionality is intended for more than just the command line—likely coming to the Codex desktop app and ChatGPT Work. An OpenAI spokesperson confirmed testing but said there are no immediate launch plans, calling it part of the company's "shared playground" culture.

This aligns with Sam Altman's recent vision of transforming ChatGPT from a reactive question-answerer into a proactive, always-on agent. OpenAI sees this as crucial for driving adoption of their most advanced models, which only a fraction of ChatGPT's user base currently uses. The company acknowledges heightened risks with persistent models—they recently referenced concerns around alignment, hallucinations, and safety in technical reports. For developers, persistent agents represent both opportunity and challenge: more powerful automation capabilities, but also greater responsibility for monitoring, sandboxing, and ensuring these tireless digital workers stay aligned with human intent.

*Source: [Wired](https://www.wired.com/story/openai-is-developing-a-persistent-ai-agent/)*

### Foundry Model Router Expands from Two Regions to 28, Refreshing Its Model Pool

Microsoft's Foundry model router has dramatically expanded from two regions to 28 for global standard deployments and 21 for data zone deployments. The model pool refresh adds Claude Opus 4.8 and GPT-5.6 while removing four deprecated models. Default deployments automatically receive pool changes, but configured subsets exclude new models until manually added. The effective context window equals the smallest model in the pool, so organizations should review their configurations to take advantage of newer models' capabilities while understanding the context window implications.
