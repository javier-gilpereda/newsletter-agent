## In Depth

### Claude Code revamps projects so you can work and pay in parallel

Anthropic has fundamentally redesigned how projects work in Claude Code, and the new implementation is all about parallelism. The old "Projects" feature was essentially a workspace organizer—separate chat histories and knowledge bases living side by side. The new lowercase "projects" (currently in beta) is something entirely different: it's a coordinator that can spin up multiple Claude Code sessions simultaneously to tackle related tasks in parallel.

Here's how it works: when you kick off a project, Claude analyzes your request, breaks it into discrete tasks, and launches each one as its own cloud session thread with its own git branch and repo copy. A coordinator agent oversees the whole operation, and if threads touch the same code, you'll see familiar merge conflicts like any other pull request. Each thread can even spawn subagents to handle distinct subtasks within that session. It's particularly useful for large coding projects where you want authorization, databases, caching, and containers all scaffolded at once.

The catch? Token consumption goes through the roof. Anthropic is upfront about this: because each thread is a full Claude Code session, projects can hit usage limits much faster than single-session work. Right now, Pro and Max subscribers with Claude Code access can use the beta (assuming they don't have legacy Projects set up), and there's a waitlist for gradual rollout. Team and Enterprise plans don't have access yet. With Anthropic reportedly posting $11.5 billion in Q2 revenue and operating profitably when stock-based compensation is excluded, this feature seems designed to accelerate both productivity and spending for power users.

*Source: [The Register](https://www.theregister.com/ai-and-ml/2026/09/18/claude-code-revamps-projects-so-you-can-work-and-pay-in-parallel/5297532)*

### Spring AI and TypeSafe Jev: Fast, Cheap, Structured Decisions

Making decisions with AI models usually means writing prompts, defining JSON schemas, parsing responses, and handling unpredictable outputs. Spring AI TypeSafe takes a radically different approach by integrating TypeSafe AI's hosted Jev API—a service designed specifically for judgment calls, not text generation. It's not a chat model; it classifies, scores, and decides based on typed questions you provide.

The API is refreshingly simple. You give it a state (the thing being judged) and a map of typed questions. Every question follows one of three primitives: Noul (yes/no returning a truth value between 0 and 1), Choice (pick one label with probabilities and confidence), or Score (place on an ordered rubric with continuous values and per-level probabilities). For example, analyzing a support ticket returns structured answers like urgency = 0.95, department = "billing" with 0.82 confidence, and frustration = 1.1 on a three-level scale—all in around 300 milliseconds. No prompt templates, no parsing.

The project is available on Maven Central as spring-ai-starter-typesafe (version 0.1.0), with auto-configuration providing a TypeSafeClient bean when you export your TypeSafe API key. It works standalone with just spring-web and Jackson, and includes Spring AI integration for judges and advisors. Seven runnable demos ship with the project. The key insight here is that option descriptions matter: bare labels like "billing, technical, sales" drop confidence to 0.60, while descriptive options like "Payments, invoicing, refunds" push it to 0.82. This is a compelling tool for routing requests, evaluating reasoning tasks, or making quick multi-agent decisions without the overhead and unpredictability of generative models.

*Source: [Spring Blog](https://spring.io/blog/2026/09/21/spring-ai-typesafe-structured-judgment)*

### A single git trick beat the safety lock on four AI coding agents

Plugin marketplaces for AI coding agents use commit hash pinning to ensure safety—locking each plugin to one specific, reviewed version of code. Researchers at Air Security just demonstrated that this protection is fundamentally broken. The vulnerability, dubbed Plugin4Shell, affects Claude Code, OpenAI's Codex, GitHub Copilot, and Google's Gemini CLI. It's a zero-click remote code execution attack requiring no user action whatsoever.

The exploit hinges on a subtle git behavior: when a name can be interpreted as both a branch and a commit hash, git quietly prefers the branch. AI agents request code at a pinned commit hash but never verify what they actually received. An attacker controlling a plugin repository can create a branch named after the pinned hash, point it at malicious code, and set it as default. The agent dutifully checks out the branch, installs the attacker's payload, and reports a clean install at the correct commit. The Gemini CLI fails differently—it fetches the right commit but then runs a checkout that a default branch named FETCH_HEAD can intercept.

The attack targets plugins already installed and trusted, exploiting automatic background updates in Claude Code and Codex. The sequence: publish something useful, pass review, ship an update to get a new pin, then create the malicious branch. Every auto-update installs the compromised code with full developer privileges—files, credentials, and system access. Anthropic patched Claude Code in version 2.1.179, OpenAI fixed Codex in 0.146.0, but Microsoft has shipped no Copilot fix, and Google won't patch the retiring Gemini CLI. GitHub claims its users are protected because it rejects hash-shaped branch names, but Air Security points out that marketplaces can live on Bitbucket or private git servers, both of which allow the exploit. With roughly 90% of Fortune 500 companies using Copilot, this unpatched vulnerability is significant.

*Source: [The Next Web](https://thenextweb.com/news/plugin4shell-ai-coding-agents-zero-click-rce-sha-pinning)*

## Also This Week

### Claude Code now supports AGENTS.md alongside CLAUDE.md

Claude Code version 2.1.277 introduces support for AGENTS.md files as an alternative to CLAUDE.md for project-specific instructions. If no CLAUDE.md exists in a folder, Claude automatically checks for and uses AGENTS.md instead. This capability is built on Claude Code mods—Anthropic's upcoming system for customizing the Claude Code harness. The AGENTS.md support ships as a built-in mod, but developers will soon be able to create custom versions of project instructions tailored to their workflows. The source code for the mod is publicly available, and Anthropic has published additional examples demonstrating how mods work.

*[Simon Willison](https://simonwillison.net/2026/Sep/18/thariq-shihipar/)*

### Google Agent Development Kit for Kotlin Reaches Feature Parity

Google has released version 1.0 of the Agent Development Kit (ADK) for Kotlin, marking it production-ready for building AI agents across Kotlin, Android, and JVM/server applications. This release brings Kotlin to feature parity with Google's ADK implementations for Python and Java, while adding Android-specific capabilities for on-device and hybrid AI scenarios. The framework enables developers to build sophisticated AI agents that can run entirely on-device, in the cloud, or in hybrid configurations—particularly valuable for mobile applications where latency, privacy, and offline functionality matter. This positions Kotlin as a first-class language for AI agent development alongside Python and Java.

*[InfoQ](https://www.infoq.com/news/2026/09/google-adk-1-0-released/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=global)*

### Introduction to Solon Framework for Java

Baeldung has published a comprehensive introduction to Solon, a lightweight Java framework that presents an alternative to Spring Boot. ### Claude Cowork and chat merge into unified Claude experience

Anthropic is consolidating Claude Cowork and the standard chat interface into a single unified Claude experience. The merger means users can seamlessly transition between quick questions and handing over complex, time-consuming tasks—Claude continues working even after the laptop is closed. This rollout targets Pro and Max plan subscribers first, gradually becoming available across the Claude app on web, desktop, and mobile platforms over the coming weeks. The consolidation addresses growing confusion about when to use Cowork versus regular Claude versus Claude Code, simplifying the product lineup while making autonomous, long-running capabilities available in the main interface.

### Prompt Caching Support in Spring AI with Anthropic Claude

Baeldung has published a guide on using prompt caching with Anthropic's Claude models through Spring AI. Prompt caching reduces costs and latency by storing frequently used prompt segments—like system instructions, large documents, or knowledge bases—and reusing them across multiple requests instead of reprocessing them each time. The tutorial covers how caching works under the hood, the limitations and variations across different Claude model versions, and practical implementation patterns within Spring AI applications. For applications with repetitive contexts or large static prompts, caching can dramatically reduce both API costs and response times.

*[Baeldung](https://feeds.feedblitz.com/~/969174386/0/baeldung)*

### Researchers used Claude to hack OpenAI

Security researchers successfully used Claude to compromise an OpenAI employee account and gain access to sensitive GitHub repositories. The demonstration highlights the dual-use nature of AI coding assistants—the same capabilities that help developers write code and automate tasks can be weaponized for social engineering and targeted attacks. While details of the specific techniques remain limited, the incident underscores growing concerns about AI-assisted cyberattacks and the security risks posed when powerful language models are applied to offensive security research. Both companies are investigating the incident and evaluating additional safeguards.

*[Ars Technica](https://arstechnica.com/ai/2026/09/researchers-used-claude-to-hack-openai/)*
