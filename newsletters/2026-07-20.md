## In Depth

### Claude Code Now Runs on Bun Written in Rust

In a move that went largely unnoticed by millions of users, Claude Code quietly switched to running on a Rust-based version of Bun with version 2.1.181 in mid-June. Jarred Sumner, Bun's creator, casually mentioned this deployment milestone while announcing the Rust rewrite, noting that "startup got 10% faster on Linux but otherwise, barely anyone noticed. Boring is good."

Simon Willison decided to investigate his own Claude Code installation and found compelling evidence. Running `strings` on the Claude binary revealed it's using Bun v1.4.0, a version that hasn't even been officially released yet (the latest public release is v1.3.14 from May). Even more telling: extracting filenames from the binary shows 563 Rust source files with paths like `src/runtime/bake/dev_server/mod.rs` and `src/bundler/bundle_v2.rs`.

This is a remarkable case study in production Rust deployment at scale. Millions of devices are now running this rewritten runtime, and the transition was so smooth that users didn't notice. The fact that a major rewrite in a different programming language can ship with only marginal performance improvements and no disruption speaks volumes about both the quality of the rewrite and the robustness of the testing process. For developers watching the Rust ecosystem, this is further evidence that Rust can deliver on its promise of safe, performant systems programming in real-world production environments.

*Source: [Simon Willison](https://simonwillison.net/2026/Jul/19/claude-code-in-bun-in-rust/)*

### Making Java Codebases AI-Agent Ready with AGENTS.md

As AI coding agents like Cursor, GitHub Copilot Agent Mode, and Claude Code become standard development tools, a new challenge emerges: how do we make our Java codebases comprehensible to these autonomous assistants? The answer, according to a new best practice, is creating an `AGENTS.md` file at the root of your project.

The concept is straightforward but powerful. Just as we've long maintained README files for human developers, we now need structured documentation that AI agents can parse to understand project architecture, conventions, and testing approaches. For Java developers, this is especially valuable given the framework-heavy nature of modern Java development with Spring Boot, Quarkus, and enterprise patterns.

The article highlights how Quarkus users have a particular advantage here with "Supersonic Subatomic Java" — ultra-fast developer loops and continuous testing that work seamlessly with AI-assisted workflows. An `AGENTS.md` might include information about your module structure, where to find integration tests, how to run the dev server, common patterns for REST endpoints, and which architectural decisions are non-negotiable.

This represents a fundamental shift in how we think about code documentation. We're no longer just writing for the developer who joins our team in six months; we're also writing for the AI pair programmer that will help that developer navigate the codebase on day one. As AI coding assistance becomes ubiquitous, expect `AGENTS.md` files to become as standard as `.gitignore` in professional Java projects.

*Source: [DZone Java](https://dzone.com/articles/agents-md-java)*

### Spring AI 2.0 Goes Generally Available with Unified Tool Calling

Spring Office Hours recently covered the fast-moving intersection of AI and Java development, with particular focus on Spring AI 2.0's general availability release. Built for Spring Boot 4 and Spring Framework 7, this major version brings significant architectural improvements for Java developers building AI-powered applications.

The headline feature is a unified tool calling model that simplifies how AI models interact with Java methods and external services. Previously, each AI provider (OpenAI, Anthropic, etc.) had slightly different approaches to function calling, requiring developers to write provider-specific code. Spring AI 2.0 abstracts these differences, letting you define tools once and use them across multiple AI backends.

Progressive tool discovery is another notable addition, allowing the framework to dynamically discover and register available tools as your application runs. This makes it easier to build modular AI applications where different components expose different capabilities to the language model. The podcast also discusses updated Model Context Protocol (MCP) support, which helps AI models access external data sources and tools in a standardized way.

For Java developers who've been watching the AI space from the sidelines, Spring AI 2.0 represents a mature, production-ready entry point. You get Spring's familiar programming model, excellent documentation, and enterprise-grade reliability applied to AI integration. The timing is particularly good given recent releases from both OpenAI and Anthropic that the podcast covers, giving Java developers access to cutting-edge language models through a framework they already know and trust.

*Source: [Spring Blog](https://spring.io/blog/2026/07/13/spring-office-hours-podcast-S5E18)*

### Claude Fable Produces Counterexample to the Jacobian Conjecture

In a stunning development that's generating intense discussion across mathematics and AI communities, Claude's Fable model appears to have produced a counterexample to the Jacobian Conjecture, a long-standing open problem in algebraic geometry. The conjecture, which concerns polynomial mappings, has resisted proof for decades. If verified, this would represent a landmark moment in AI-assisted mathematics, demonstrating that large language models can contribute meaningfully to advanced mathematical research. The claim has generated 421 points and 255 comments on Hacker News as mathematicians work to verify the counterexample's validity.

### Making MCP Servers Stateless for Cloud-Native Java Deployments

The Model Context Protocol revolutionized how LLMs connect to real-world data, but early implementations relied on stateful, long-lived sessions that created scaling nightmares. The newest MCP specification updates solve this with stateless server support, eliminating sticky sessions and complex load balancing requirements. For Java developers building enterprise AI tools, this means you can now deploy MCP servers as standard stateless microservices behind standard load balancers, handling thousands of concurrent agent workflows without memory overhead concerns. This architectural shift makes MCP much more compatible with cloud-native Java patterns.

*[DZone Java](https://dzone.com/articles/stateless-mcp-servers)*

### Preventing Cache Stampedes with Java 21 Virtual Threads

API versioning typically forces a painful choice: break backward compatibility or maintain multiple hard-coded endpoints. This article explores a third option using dynamic API translation with intelligent caching. The challenge is cache stampedes — when cache expires under high load, hundreds of requests simultaneously hit your translation layer. Java 21's virtual threads provide an elegant solution by allowing lightweight request coordination without traditional thread-pool exhaustion. The article demonstrates practical patterns for using virtual threads to implement request coalescing, ensuring only one thread performs expensive translation work while others wait efficiently for the cached result.

*[DZone Java](https://dzone.com/articles/java-21-cache-stampedes)*

### Logging Request and Response Bodies in Spring HandlerInterceptor

Baeldung covers a common Spring MVC challenge: how to log HTTP request and response bodies within a HandlerInterceptor. The difficulty stems from input streams being consumable only once, so naive logging approaches break downstream request processing. The tutorial demonstrates proper techniques using ContentCachingRequestWrapper and ContentCachingResponseWrapper, which buffer the content while still allowing normal servlet processing. This pattern is particularly useful for debugging, audit logging, and monitoring in production Spring Boot applications without disrupting normal request flow.

*[Baeldung](https://feeds.feedblitz.com/~/960269651/0/baeldung~How-to-Get-The-RequestBody-and-ResponseBody-in-HandlerInterceptor)*

### Security Researcher Finds Data Exfiltration Vulnerability in Claude

Security researcher Ayush Paul discovered a data exfiltration vulnerability in Claude's web_fetch tool despite Anthropic's design efforts to prevent such attacks. While Claude's architecture was specifically built to avoid "lethal trifecta" attacks (where AI has access to private data, can fetch online content, and can exfiltrate through URLs), Paul found a workaround. The vulnerability demonstrates the ongoing cat-and-mouse game in AI security, where even well-designed systems can have exploitable edge cases. This reinforces the importance of defense-in-depth approaches when deploying AI systems with access to sensitive data.
