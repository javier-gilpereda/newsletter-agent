### Semble: Code Search That Cuts Claude Code's Token Usage by 98%

If you're using Claude Code or Cursor on large codebases, you've probably felt the pain of token bloat from grep-and-read workflows. Semble, a new open-source tool from MinishLab, tackles this head-on with intelligent code search built specifically for AI agents.

What makes Semble interesting is its speed and efficiency. It indexes an entire repository in roughly 250 milliseconds and answers natural language queries in about 1.5 milliseconds—all running on CPU with no API keys or GPU required. Instead of agents grepping entire files and burning through tokens, Semble returns only the relevant code snippets. The project benchmarks show it uses approximately 98% fewer tokens than traditional grep-and-read approaches while maintaining 99% of the retrieval quality of code-specialized transformer models.

Semble works as an MCP server that integrates directly with Claude Code, Cursor, Codex, and other MCP-compatible agents. You can also use it via command-line tools added to AGENTS.md files. The workflow is straightforward: start with `semble search` to find relevant chunks using natural language queries like "authentication flow" or "save model to disk," then use `semble find-related` to discover similar code based on file paths and line numbers from your initial results.

What matters here is the practical impact on development workflows. Large codebases can quickly exhaust context windows or rack up costs when agents read full files unnecessarily. Semble's approach—indexing locally, searching semantically, and returning only what's needed—represents a smarter architecture for agentic coding tools. The project is actively maintained, supports both local paths and git URLs, and automatically re-indexes when files change. For teams running Claude Code or similar tools at scale, this could meaningfully reduce both token costs and response latency.

### Claude Code Gets Routines for Automated Workflows

Anthropic has launched Routines for Claude Code, a feature that shifts AI coding assistance from interactive sessions to persistent, automated workflows. Routines run on Anthropic's cloud infrastructure and can be triggered by schedules, API calls, or external events—no local cron jobs or servers required.

A routine combines a prompt, repository access, and connected tools into a repeatable workflow. Scheduled routines handle recurring tasks like bug triage, documentation updates, or automated pull request generation. API-triggered routines expose authenticated endpoints, letting deployment pipelines or monitoring systems launch Claude Code sessions via HTTP requests. The webhook-based routines integrate with GitHub events, automatically responding when pull requests meet specific conditions—monitoring updates, addressing comments, tracking CI failures, and operating throughout the PR lifecycle.

Early adopters are already using Routines for automated issue triage, deployment verification, alert analysis, and cross-language SDK synchronization. One example described a Python SDK change that automatically triggers a routine to port updates to Go and open a corresponding PR. Another uses monitoring alerts to trigger automated debugging sessions before engineers investigate incidents.

Community reaction has been mixed. Some developers see enormous potential for automating PR reviews and CI/CD workflows. Lead engineer Mike Darlington called it "massive," highlighting the ability to trigger AI webhooks directly from observability dashboards. Others expressed frustration with Anthropic's rapid feature releases while existing issues—model degradation, downtime, quota limits—remain unresolved.

Routines reflects a broader industry shift toward asynchronous, event-driven AI coding agents that operate continuously in cloud environments rather than interactive local sessions. Compared to tools like Cursor, GitHub Copilot agents, and OpenAI Codex workflows, Claude Code Routines emphasizes persistent background execution tied directly to repositories, APIs, and operational systems. For teams managing complex workflows across multiple repositories and environments, this could fundamentally change how AI assists with software development.

### Spring AI Adds Anthropic Agent Skills for Structured Outputs

Spring AI now supports Anthropic agent skills, bringing structured output capabilities to Spring Boot applications through direct Claude integration. This update from Baeldung demonstrates how developers can leverage Claude's agent capabilities within the Spring ecosystem for predictable, format-specific responses.

The integration addresses a common pain point: getting reliable, structured data from large language models in production Spring applications. While LLMs excel at natural language generation, production systems often need JSON schemas, specific data formats, or validated outputs. Anthropic's agent skills framework provides this structure, and Spring AI now wraps these capabilities in familiar Spring abstractions.

For Java and Kotlin developers working with Spring Boot, this means you can define agent skills as Spring beans, configure them through standard Spring configuration, and get type-safe, structured responses from Claude without managing low-level API calls or parsing unstructured text. The approach fits naturally into existing Spring dependency injection patterns and works alongside other Spring AI components like embedding stores and retrieval chains.

What makes this particularly relevant is the growing intersection of enterprise Java applications and AI capabilities. Spring Boot has become the de facto standard for building production Java microservices, and integrating AI features—chatbots, document processing, intelligent routing—increasingly requires more than simple API calls. Spring AI's abstraction layer handles concerns like connection pooling, error handling, retry logic, and observability, while Anthropic's agent skills provide the output structure.

The Baeldung tutorial likely covers practical implementation details: configuring Anthropic clients, defining skill schemas, handling errors, and integrating with Spring's testing framework. For teams already invested in the Spring ecosystem, this native integration removes friction and provides a production-ready path to adding structured AI capabilities to existing applications. It's another sign that AI features are moving from experimental add-ons to first-class citizens in enterprise Java development.
