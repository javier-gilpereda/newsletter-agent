## In Depth

### I Didn't Let Claude Upgrade My Java App. I Let It Work for Me.

Upgrading a legacy Spring Boot 2.x service from Java 8 to Java 21 is the kind of project that makes developers wince—especially when you're rusty on Java and every change feels like defusing a bomb. One developer solved this by using Claude Code, but with a crucial twist: they kept control while letting AI do the heavy lifting.

Instead of following Claude's textbook advice (hop through Java 11 and 17, run OpenRewrite recipes, deploy five specialist reviewer agents), they built a pragmatic two-agent system. The Migrator writes code, while a separate Verifier reviews it with fresh context—never grading its own work. The key insight: "the agent that writes the code never grades it." A fresh Claude session acts like a colleague who wasn't in the room when you made that questionable decision.

The migration followed a detailed checklist in MIGRATION.md, tackling build files, javax-to-jakarta migrations, Spring Security's removed WebSecurityConfigurerAdapter, and Hibernate 6 changes. Each item had clear scope, acceptance criteria, and a four-state marking system: to-do, Migrator-done, Verifier-passed, and human-approved. Before starting, they tagged the Java 8 codebase and saved real API requests for comparison.

The workflow was iterative: Migrator completes an item, Verifier checks both new changes and all previous items, and three failures trigger human intervention. Only after manual review does work proceed. The result? A successful upgrade to Java 21 and Spring Boot 3.3.5 without the pain of doing it all manually or blindly trusting AI output. It's a masterclass in using AI as a powerful assistant while maintaining engineering judgment.

### Spotify More Than Doubled Monthly Code Changes as AI Accelerated Development

Spotify's AI adoption story sounds impressive on paper: monthly merged changes jumped from 8,100 to 17,000 year-over-year in August, driven by AI-assisted development tools. But the real story is about what happens after the code gets written.

The streaming giant operates nearly 3,000 production services supporting 777 million monthly active users and handles 11-12 million backend requests per second. As AI-generated code flooded in, Spotify discovered its quality controls hadn't kept pace. They experienced several incidents, including a content processing pipeline delay when a scheduled batch workload, quality improvements, and a scheduling bug combined to reduce throughput by 10%—causing hours-long delays for the 500,000+ daily uploads.

Spotify uses Fleet Management for standardized maintenance and recently added Honk, a background coding agent running Claude via the Agent SDK. While a Java migration across backend services took just three days, an automated dependency upgrade that passed existing checks still failed in production. The company has responded by strengthening safeguards, expanding rollback capacity, and scheduling automated changes during team working hours.

The composition of work shifted too: quality and optimization rose from 27% to 31% of merged changes, while maintenance fell from 31% to 25%. Crucially, Spotify reports no material increase in rework and found no direct contribution from AI-authored code in incidents—but change volume had outpaced verification controls. This aligns with recent Google DORA research showing AI adoption correlates with higher throughput but potentially lower stability, emphasizing the need for automated testing, version control, and fast feedback loops when deploying AI-assisted development at scale.

### AI coding agents generate more code, but not more software

Harvard researchers just confirmed what many developers suspected: AI coding tools generate mountains of code but don't necessarily ship more features. By analyzing 300 million work events across 700+ software firms and 700,000 employees, they found a stark disconnect between code production and actual output.

The numbers are dramatic. After introducing AI coding agents, firms saw a 30% increase in total lines of code, 20% more commits, and 23% more pull requests. Yet the resolution rate for Jira-tracked Issues and Epics—actual software features—showed no statistically significant change. The culprit? Human code review became a massive bottleneck.

Review times ballooned 49% on average after AI agents arrived. Pull requests requiring changes nearly doubled, and comments per pull request increased 35%. This makes sense: AI can churn out code quickly, but humans still need to verify it actually works, handles edge cases, and integrates properly. The efficiency gained during coding evaporates in downstream verification.

Organizations responded by increasing code reviewers by 14%, but found "little evidence that firms increase software output or reduce employment" from AI tools. The researchers conclude that while AI excels at generating code, the constraint has shifted to validating that code. This aligns with recent Spotify findings and challenges the narrative that AI automatically multiplies developer productivity. The bottleneck moved—it didn't disappear. Until verification catches up with generation, AI coding agents will produce impressive commit graphs but not necessarily more shipped software.

*Source: [Ars Technica](https://arstechnica.com/ai/2026/10/ai-coding-agents-generate-more-code-but-not-more-software/)*

### Github Migrates Copilot Runtime to Rust with AI-Assisted Rewrite

GitHub successfully migrated over 800,000 lines of Copilot runtime code from TypeScript and Node.js to Rust in just 14.5 weeks using AI-assisted development. The incremental migration leveraged N-API interoperability for gradual transition, extensive automated testing, thorough human review, and 128 pull requests—all while continuing to ship regular releases. This represents one of the largest AI-assisted rewrites completed to date and demonstrates that AI can handle substantial refactoring projects when properly managed with human oversight, automated testing, and incremental delivery approaches.
