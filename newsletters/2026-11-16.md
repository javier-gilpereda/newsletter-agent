## In Depth

### Anthropic Outlines its AI-Powered Code Review Process for Claude Code

Anthropic has pulled back the curtain on how its Claude Code team handles code reviews as AI agents contribute an ever-growing share of its codebase. The approach combines multiple layers of automated verification, AI-powered reviews, and risk-based human approval—designed to cut manual review time without spiking regressions or incidents.

Between June and September, merged pull requests more than doubled while reverts dropped by over 40%. Instead of traditional line-by-line reviews, the team moved verification earlier: Claude runs tests, builds, and linters before even opening a PR, and a separate agent reviews changes in a fresh context. Every PR then passes through automated checks where multiple Claude-powered reviewers independently inspect for bugs, with another group verifying findings. A dedicated security review can block merges if issues remain unresolved.

Human oversight scales with risk. Low-risk changes like documentation updates may need zero human approval. Medium-risk changes require one reviewer, high-risk need two, and sensitive areas like CI workflows always demand human eyes. To prevent review fatigue, cycles cap at three rounds before authors reconsider their approach, and subsequent reviews focus only on new changes.

The results are striking: internal PRs passing after one review-and-fix round jumped from 65% to 78%, while those requiring five-plus rounds plummeted from 8.9% to 1.5%. Still, humans remain accountable for architecture, product direction, and final outcomes—and the person directing an AI agent owns the code it produces. Merged changes typically roll out behind feature flags, get tested internally, then gradually reach users. Incidents and reverts feed back into evaluation datasets that continuously improve the automated reviewers. It's a compelling glimpse at how engineering workflows evolve when AI becomes a first-class contributor.

### Building an AI-Powered Code Review Assistant in Java

Code review is high-leverage but expensive—it consumes senior developer time at scale. What if you could offload the first pass to an LLM that understands Java idioms, common anti-patterns, SOLID principles, and security pitfalls, returning structured, actionable feedback before a human even opens the PR?

This DZone tutorial walks through building exactly that: a self-contained Java application that accepts a Java source snippet, sends it to an LLM, and receives back a detailed review. The guide covers integrating with modern LLM APIs, structuring prompts to elicit useful feedback (think: code smells, potential null pointer exceptions, naming conventions, performance red flags), and parsing the response into a format your team can act on.

The beauty of this approach is its modularity. You can plug it into existing CI/CD pipelines, run it as a pre-commit hook, or embed it in pull request automation. The LLM acts as a tireless junior reviewer that never misses obvious issues—freeing human reviewers to focus on architecture, business logic, and nuanced design decisions. It's not about replacing human judgment; it's about augmenting it and making better use of limited review bandwidth.

For Java teams already managing PR queues and looking to improve code quality without hiring more senior engineers, this is a practical, implementable solution. The tutorial provides working code, so you can adapt it to your stack, experiment with different LLMs, and tune prompts to match your team's standards. It's a hands-on entry point into the increasingly relevant world of AI-assisted development workflows.

### Rate Limit Information from Anthropic API Response Headers Using ChatResponseMetadata in Spring AI

If you're integrating Claude into a Spring Boot application, understanding rate limits is critical—especially as AI features scale. This Baeldung tutorial shows how to extract rate limit metadata from Anthropic API responses using Spring AI's ChatResponseMetadata class, giving you visibility into request quotas, token limits, and usage in real time.

The setup is straightforward: add spring-ai-starter-model-anthropic to your dependencies, configure your API key and model (like claude-sonnet-5-5) in application.properties, and you're ready to go. The tutorial defines a MetadataResponse record to structure the data you'll return—model name, rate limits, token counts, and the generated content itself.

In the controller, you use ChatClient to send a prompt, retrieve the ChatResponse, then call getMetadata() to access a RateLimit object. This object exposes getRequestsLimit(), getRequestsRemaining(), getTokensReset(), getTokensLimit(), and getTokensRemaining()—everything you need to monitor your API consumption and avoid unexpected throttling. You also get token usage details via getUsage(), which breaks down prompt tokens and completion tokens.

This isn't just academic. If you're building production features with Claude—chatbots, content generators, code assistants—you need to know when you're approaching limits so you can queue requests, alert users, or switch models dynamically. Spring AI abstracts the boilerplate, but this tutorial ensures you're extracting the metadata that matters. It's a small but essential piece of building resilient, well-monitored AI integrations in Java.

### Prompting Claude Fable 5.2

Claude Fable 5.2 pays close attention to code ownership cues in prompts. In Anthropic's testing, when prompts presented a codebase as someone else's or said nothing about ownership, the model tended to add to existing structure—even duplicating code. When the prompt framed the codebase as the model's own, it often consolidated duplicates and made related fixes unprompted. The takeaway: if you want structural improvements and refactoring, explicitly tell Claude it owns the code. It's a subtle but powerful prompting technique for better results.
